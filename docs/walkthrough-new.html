Code walkthrough · pagebrief v0.3.0

Any web page, as compact typed text.

pagebrief is an MCP server that drives Chrome over raw CDP and hands an agent a short, typed view of a page. Repeat visits to a page type are answered from page maps: fields a large model located once and plain code checks on every load. This page walks through the code, the one bug worth a closer look, and what the benchmark has and has not shown.

TL;DR

An agent calls open, find or read. The engine loads the page once over CDP, then either answers from a checked page map or falls back to a plain text view. On the repeat-visit track, mapped runs cost a median $0.0032 per task against $0.0113 for Playwright MCP, at the same 100% success, and about the same seconds. On the 60-task main track, pagebrief is 4.8x lighter on tokens than Playwright MCP and 1.1x cheaper per task, but about 2 seconds slower.

02

Request path

The agent only ever talks to the MCP server. Everything under it is swappable.

    Key files
  • src/engine.tsQueues opens, keeps the last 5 pages, applies maps, counts missing-field streaks.
  • src/browser.tsNever calls Runtime.enable; one evaluate extracts everything.
  • src/maps/apply.tsReads and checks each field. A failure is never shown.
  • src/page/view.tsPure functions that render the text view, diffs and bot-check reports.
  • src/net/guard.tsRefuses localhost and private networks unless allowed.

What happens on one open

1

Guard the URL

Localhost and private-network addresses are refused unless --allow-private. Behind a proxy the connected-address check is off, so redirect hops are checked by name.

src/net/guard.ts
2

Load once, capture JSON

Navigate, wait for network quiet (event streams are not waited for), keep every JSON response the page loaded.

src/browser.ts · load()
3

Extract in one evaluate

An in-page script returns visible text, meta, JSON-LD, forms and bot-check signals. Invisible text is dropped before the agent sees it.

src/page/extract-script.ts
4

Look for a map

Maps are keyed by host and a URL path pattern: * is one segment, ** the rest. No map means the plain view, and the agent can ask for teach.

src/maps/pattern.ts · store.ts
5

Check every field

Each field is read from its location and checked for type and shape. All pass: typed fields. Any fail: the text view, never a guessed value.

src/maps/apply.ts · applyMap()
03

Design choices

Three ways to give an agent a page. Tool definitions are re-sent every turn, so short definitions and few turns matter as much as page size.

A

Accessibility snapshot

What Playwright MCP returns: the whole page as a tree, plus a large tool set.

Handles any interaction
Largest definitions and pages; 25,620 median tokens in the repeat track
B

Plain fetch

No browser. One tool that downloads HTML and strips it.

Cheapest to run; 5.9 s median
No JavaScript, no captured JSON; live retail and job sites block it
C

Typed view + maps

Real browser, best data source first, checked fields on repeat visits.

Cost drops sharply once a page type is mapped
A failed check degrades to text, not to a wrong answer
First visit to a page type has no map; teaching spends a large-model call

Source order for a page view: WebMCP tools, JSON the page loaded, forms and labels and text, a model only as a last resort and always behind an interface.

05

Page maps

Four roles, kept apart on purpose: a teacher (large model, once per page type), a checker (plain code, every load), a student (small model, repairs), and an offline grader that labels failures.

bench/maps/hex.pm.json (shape, abridged)
// a map is keyed by host and a path pattern
{
  "host": "hex.pm",
  "pattern": "/packages/*",
  "fields": [
    { "name": "downloads", "type": "integer",
      "at": { "from": "text", "regex": "Downloads\\s+([\\d ,]+)" },
      "example": "..." },
    { "name": "license", "type": "string", "optional": true,
      "at": { "from": "jsonld", "path": "license" } }
  ]
}

Field names and location kinds are real (src/maps/types.ts); the values here are a sketch, so open the file in bench/maps/ for the actual regexes.

Where a field can live

doc · the page is a JSON documentjson · a response the page loadedjsonld · structured datameta · a meta tagtext · label-anchored regex

Rules the checker enforces

Fail closed.

A missing or wrong-kind value fails the whole map and the text view is shown. Regexes with nested quantifiers are rejected (unsafeRegex) so a long page cannot stall the checker.

Optional is not free.

An optional field may be absent, but if it is missing on 3 loads in a row the engine treats the location as broken (OPTIONAL_MISS_LIMIT).

Shared maps are screened.

Export strips cost data and local hosts. Import is checked, marked imported, and never overwrites your own map unless --replace.

No false claims about the student.

The small model is a prompted model. It is called "trained" or "distilled" only after a fine-tune on teacher labels exists; none does yet (docs/finetune.md).

The number bug

hex.pm prints download counts with a space between thousands. The first number parser read 168 360 as 168, so the map "passed" with a wrong value. This is the change that fixed it (commit 5b17055), followed by a re-teach of the maps.

The checker file is the one place a wrong value can reach an agent, so it gets the closest read. The SFT exporter ran on a few pages only.

How it was found and closed

found

Wrong value passed the check. The map for hex.pm read downloads as 16 instead of 16,461,343. Type and shape checks both accepted it.

cause

The number pattern treated a space as the end of the number. The first digits were a valid number, so nothing flagged it.

5b17055

Fixed with tests. Space, non-breaking and thin-space separators are grouped when followed by three digits; European 1.234,56 is handled; v1.2.3 and ab12cd are not numbers.

d848005

Maps re-taught with the fixed parser and the map evaluation rerun on 2026-11-11, using claude-opus-5-5.

open

One finding remains: rv-hn-2 has a missing title field on the final map (59 of 60 hits). Not yet investigated.

08

Actions

The do tool exists only when actions are switched on. Every action carries a risk label and returns a diff of the page, so the agent sees what changed.

LabelMeaningSource
readLooks at something: follow a link, search, filter, sort, page.src/actions/risk.ts
writeChanges something on a server: a post, a save, a cart.
dangerousMoves money, deletes or closes things, signs out, or changes credentials.

Labels come from an element's words and its form, so they are a guard and advice, not a promise. Hard limits regardless of label: it never types into password fields and never uploads files. A policy (actionPolicy) sets the highest label an agent may run.

09

Benchmark

Headless Claude Code (claude -p, Sonnet 5.5, effort medium) drives each tool as an MCP server on the same tasks. Cost is the CLI's list-price estimate; the runs used a subscription.

Repeat-visit track: 60 tasks, one repeat, 300 runs (complete)

Every tool succeeded on all 60 tasks. Mapped runs are about 3.5x cheaper than Playwright MCP, but seconds are roughly level: plain fetch is fastest (5.9 s), and unmapped pagebrief is slower than Playwright by 0.3 s here. Cost was not the only thing that moved; the mean is 1.1 tool calls against 2.3.

11

Decisions and honest gaps

Why raw CDP, not Playwright

The product has to sit under a stable agent-facing surface so the browser can change (Chrome now, Lightpanda later). Playwright and Puppeteer stay out of the product and appear only as baselines, so the comparison is fair.

Why checks fail closed

A wrong typed value is worse than a long text view: the agent trusts it. So any failed field sends the whole page back to the text view, and the hex.pm bug above is the reason the number rules are strict.

Why node:test and not vitest

vitest 5.1.0's peer dependencies broke npm install here.

Known limits

Live retail and job sites block plain HTTP; openlibrary.org, pypi.org and metacpan.org serve bot checks to headless browsers (openlibrary was replaced by hex.pm in tasks v2).

Maps exist for six sites, taught by one teacher model. Generalising to unseen sites is not measured by the repeat track.

Concurrency 2 on a 16 GB machine; at 3, Windows ran out of memory after about 220 runs.

Not measured at all: a fine-tuned student, Lightpanda, and anything beyond one repeat.
